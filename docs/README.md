## 维护顺序

1. 先阅读项目规范、版本范围说明和路线图，再核对新版实际代码；旧版只读参考。
2. 规则变化先改 `CLAUDE.md`；使用、架构、命令变化分别更新对应指南，不把实现计划当作已完成事实。
3. 验证后更新 `ROADMAP.md`；较长的阶段及验证历史放入 `docs/history/`，保留日期、基线和相对链接。
4. 新增文档补进本索引；已有历史路径继续保留，不以文档整理为由删除文件或覆盖用户改动。
