# 项目审查、修正与优化提示词

```text
请对当前 IELTS Studio 项目进行系统审查、问题修正与必要优化。目标是保证学习流程正确、浏览器记录可靠、音频播放稳定、桌面和手机操作顺畅。所有判断必须基于当前代码和实际验证，不要为了优化而扩大功能范围。

项目根目录：/Users/lhp/Desktop/codeProject/ielts-dev

先阅读项目内的 CLAUDE.md、ROADMAP.md、README.md，并通过文档索引阅读新旧版本范围、使用指南、架构说明、开发维护指南、个人词库方案与现有代码审查记录。同时检查 Git 状态，保留已有修改；文档与代码、提交状态不一致时明确指出，不凭历史记录判断当前问题。

项目使用 Vue 3、Vite、PrimeVue 4，无后端，构建为纯静态网站。共有单词学习、听力、同义词、单词播放四个模块、五个 HTML 入口，首页与单词入口加载同一模块。只审查和修改新版，旧独立 HTML、旧脚本和旧文档保持冻结。注意旧目录中仍有新版入口、构建数据和音频，按具体文件判断范围。

按以下方式执行：

1．先只读审查，梳理「输入与解析 → 页面状态 → 学习／播放 → 记录保存 → 刷新恢复」的完整链路，建立问题清单。
2．问题必须包含优先级、触发条件、复现步骤、期望与实际行为、代码位置、影响及修复方向。区分已复现缺陷、待验证风险和优化建议，不把猜测当结论。
3．证据明确、范围小、风险低的修复直接完成；大改动、跨模块改动或高风险改动先提交方案，说明改动范围与验证方式，确认后再实施。只读跨模块审查可以继续推进。
4．修复后验证，并同步项目进度和相关现行文档。不要只给泛泛建议，也不要顺手重构、改版或添加功能。

重点审查以下内容：

一、单词学习

- 内置词库与个人词库的切换、搜索、分组、学习位置、笔记、难度和掌握状态是否正确隔离。
- UTF-8 CSV／TXT 的解析、BOM、引号、字段内逗号与换行、必填字段、去重规则、预览确认与重名处理是否符合现有方案。
- 单文件 2 MiB、去重后 5000 词条的限制是否在边界处正确生效；失败或取消导入是否保留原词库和记录。
- 单词卡片、中文选择题、听音拼写是否正常；难度是否始终为 0～10，答错＋3，同题重复提交不重复计分，答对或标记掌握不自动降低难度。
- 难度复习的搜索、范围、排序、到期筛选及实际练习词表是否一致。
- 本轮进度、词库统计、每日汇总、最近 7／30 天和连续学习是否正确去重；导入不计学习，删除个人词库不回扣每日汇总。
- 个人词条是否优先完整匹配已核验的本地 MP3，无匹配才使用 Web 语音；已有 MP3 播放失败是否明确提示并暂停。

二、听力

- 以现有 corpus.json 为语料来源，检查章节、分组、语料顺序和音频映射，避免混入旧词库中的额外数据。
- 自定义语料对换行、中英文分号与逗号的解析是否正确，完整含逗号语料及词组空格是否保留。
- 顺序／乱序、逐词重复、整轮循环、单词与词组倍速、间隔、暂停、继续、重播和跳过是否一致；暂停是否同时暂停计时。
- 答错、查看答案、超时、重复提交及切换下一题是否正确处理，上一题反馈不能残留。
- 听音不写听写成绩；只有完整分组听写完成才记录章节成绩，子集、错词复练和包含音频跳过的练习不能混入。
- 错词本的筛选、排序、多选、复练、等级与统计是否正确。
- 缺失或失败的原声音频必须明确提示，不能使用合成语音替代。

三、同义词

- 默认示例与已保存词库的恢复优先级是否正确；搜索是否保留完整分组。
- TXT／JSON 多文件导入、严格 UTF-8、中文标签仅展示不发音、合并顺序和整批拒绝是否符合规范。
- 验证单文件 2 MiB、每批 10 MiB、总计 10000 词条、单组 200 条、每页 50 条和最多 20 个缓存文件的边界。
- 缓存多选顺序、同名替换、先进先出淘汰及删除范围是否正确；删除缓存不能影响已加载词库、已有笔记或其他模块记录。
- 每词重复、每组循环、上下词、高亮、分页与播放位置是否一致，内存不能随循环次数复制全部队列。
- 播放行居中是否立即生效、跟随当前组、支持最后一组，且不打断播放、不滚动已打开弹窗的背景。
- 保留已有笔记的展示、编辑与移除，不新增笔记入口。

四、单词播放

- 粘贴词表的分隔、中文过滤、大小写与连续空白去重、输入限制及提示数量是否正确。
- 顺序播放结束、乱序、跳转、暂停、继续和重播是否正确处理当前位置与完成状态。
- 听写模式是否正确隐藏拼写，判题是否遵守现有大小写和空白规则，切题是否清理上一题状态。
- 刷新是否恢复词表、设置与位置，且不会自动发音。
- 清空操作是否只影响当前模块的新版记录，不影响原参考页和其他模块。

五、共用播放、存储与界面

- 检查异步音频回调、Web 语音取消、重复点击、快速切词、切换模块及组件卸载，防止重叠播放、旧回调串入新题、计时器残留和重复计分。
- 验证语音列表延迟加载、可用的手动选择恢复及各模块现有默认发音规则；播放失败不能静默忽略。
- 同义词与单词播放的手动切词、点击词条和重播不能开启原本关闭的自动播放。
- 沿用现有 IndexedDB 数据库、版本 1 和 kv 对象存储，不调整结构。每条新记录包含键、时间戳和值后不得超过 8 KiB。
- 区分首次读取失败、真正空记录与保存失败；读取失败不能用默认快照覆盖原数据，保存失败必须保留待保存内容并支持重试。
- 验证分块内容缩短、替换、清空和缓存淘汰后的多余键回收，以及 IndexedDB 成功写入后的 localStorage 镜像清理，防止旧数据复活。
- 检查个人词库的多标签页并发导入、删除和同步，避免旧页面覆盖最新目录。使用隔离测试数据，不清除真实学习记录。
- 验证 localStorage 回退的错误提示与恢复行为，不声称它具有 IndexedDB 的事务原子性。
- 日期、日统计和每日浏览器提醒统一按北京时间，检查跨午夜及历史日期键保留。
- 快捷键不得拦截 Ctrl／Meta／Alt 组合、输入控件、按钮、链接或弹窗操作。
- 保留现有顶部导航与浅色玻璃风格，检查手机窄屏、长文本、选择面板、弹窗、焦点、触控及显示隐藏后的布局。
- 检查导入内容和笔记渲染是否存在脚本注入，以及运行代码、文档和日志是否意外暴露凭据；发现时不输出真实凭据。

六、构建与性能

- 核对数据准备顺序：先听力，再单词；不要手工修改生成数据。
- 检查五个入口、动态加载、章节数据、音频索引与实际构建资源的一致性，特别验证中文、空格、加号、百分号和问号文件名的实际 URL。
- 构建应写入新的独立目录，全部成功后才能更新最新指针；失败不能指向不完整产物。
- 只针对实际瓶颈优化，如重复计算、过量渲染、全量序列化、重复写入或不必要的资源加载。先记录可复现的基线，再验证优化收益，不凭感觉拆组件或加缓存。

验证要求：

- 先运行现有测试建立基线。生成数据缺失时，按顺序运行：
  npm run prepare:listening
  npm run prepare:words
- 修复数据、判题、播放或并发问题时，优先建立最小复现，并增加必要的回归测试；纯文案和低影响排版改动不机械增加测试。
- 修复后运行 npm test、npm run build、git diff --check，并用真实浏览器检查相关流程、刷新恢复及桌面／手机布局。
- 根据实际改动覆盖空输入、无效输入、容量临界值、快速操作、读取／保存失败和重试，避免用正常路径测试代替异常验证。
- 历史审查中的已修复事项先复核再判断；Windows 原生快捷键和生产发布验收仍按实际环境标记，不能用本地或模拟测试冒充。
- 环境不具备时明确写「未验证」，说明缺少的条件，不把未验证事项记为已完成。

实施边界：

只修改与已确认问题直接相关的文件，优先现有依赖和最简单实现。不新增后端、登录、云同步、学习记录备份／导入／导出，不升级依赖或引入新的 UI、路由、状态管理库。

删除仓库文件或目录、Git 回滚／覆盖／改历史／推送、修改环境变量或凭据或 CI/CD、数据库结构与迁移、全局依赖、系统配置及公开发布，必须先取得明确授权。Cloudflare 操作每一步单独说明并确认。本次审查不包含生产部署。

最终交付：

按优先级汇报关键问题、实际修复、修改文件、验证结果、必要的前后性能对比，以及未完成事项和原因。新审查结果补充到现有审查记录，保留历史编号与验证日期；同步 ROADMAP.md，只有实现并验证通过的事项进入「已完成」，其余明确保留为待办或待确认。
```
